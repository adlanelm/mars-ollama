# Embedder A/B: snowflake-arctic-embed2 vs Qwen3-Embedding-0.6B (2026-10-16)

**Verdict: keep `snowflake-arctic-embed2` and set Open WebUI's `RAG_EMBEDDING_QUERY_PREFIX="query: "`. Qwen3-Embedding-0.6B was removed again.**

- **Swedish:** snowflake with its prefix beats Qwen3 by about 0.10 nDCG@10 on both sets.
- **English (SciFact):** the two are about even.
- **Speed:** Qwen3 is 2.5× slower to index on the CPU.
- The bge-reranker-v2-m3 stage narrows the quality gap but doesn't close it on Swedish.

## Setup

- Script: `bench/embed-ab.py`, via llama-swap `/v1/embeddings` and `/v1/rerank` (llama.cpp b11580, CPU embedders `-t 8`).
- Every variant uses only what Open WebUI can express: one global query prefix and no document prefix.
- Documents are cut to 2000 characters, about one Open WebUI chunk.
- Up to 300 queries per set, a fixed random sample (seed 0).
- The rerank column is bge-reranker-v2-m3 (GPU) over the embedder's top 20, which is what Open WebUI does with hybrid search on.
- Qwen3 instruction: `Instruct: Given a web search query, retrieve relevant passages that answer the query\nQuery:` (the model card's format).

| Set | Language | Corpus | Queries |
|---|---|---|---|
| SweFaqRetrieval (MTEB) | sv | 511 | 300 of 513 |
| SwednRetrieval (MTEB, test) | sv | 2046 | 300 of 1024 |
| SciFact (MTEB) | en | 5183 | 300 |

Public data, no personal data. To reproduce, download the parquet/jsonl files from `huggingface.co/datasets/mteb/{SweFaqRetrieval,SwednRetrieval,scifact}` into a data dir with the same layout, then run `bench/embed-ab.py DATA 300`. The full run took 1 h 45 min, mostly CPU document embedding.

## Results

| Set | Variant | nDCG@10 | Recall@20 | nDCG@10 after rerank |
|---|---|---|---|---|
| SweFaq (sv) | snowflake, no prefix (Open WebUI default) | 0.758 | 0.937 | 0.778 |
| SweFaq (sv) | snowflake, `query: ` | 0.782 | 0.950 | 0.777 |
| SweFaq (sv) | qwen3-0.6b, no instruction | 0.682 | 0.893 | 0.759 |
| SweFaq (sv) | qwen3-0.6b, instruction | 0.683 | 0.890 | 0.765 |
| Swedn (sv) | snowflake, no prefix (Open WebUI default) | 0.772 | 0.900 | 0.833 |
| Swedn (sv) | snowflake, `query: ` | 0.818 | 0.925 | 0.823 |
| Swedn (sv) | qwen3-0.6b, no instruction | 0.678 | 0.822 | 0.769 |
| Swedn (sv) | qwen3-0.6b, instruction | 0.705 | 0.853 | 0.795 |
| SciFact (en) | snowflake, no prefix (Open WebUI default) | 0.693 | 0.859 | 0.717 |
| SciFact (en) | snowflake, `query: ` | 0.705 | 0.874 | 0.726 |
| SciFact (en) | qwen3-0.6b, no instruction | 0.684 | 0.872 | 0.725 |
| SciFact (en) | qwen3-0.6b, instruction | 0.699 | 0.873 | 0.721 |


The rerank column moves only within ±0.01 when the query prefix changes: 0.778/0.777, 0.833/0.823, 0.717/0.726. That is within noise for 300 queries. With hybrid search on, the prefix pays off mainly through Recall@20, the candidates the reranker gets to see, and in setups where reranking is off.

## Indexing speed (CPU, the same 300 Swedn documents, 344k characters, nothing else running)

| Model | Time | Characters/s | Tokens/s | Tokens for the same text |
|---|---|---|---|---|
| snowflake-arctic-embed2 (F16) | 61.7 s | 5576 | 1329 | 82,076 |
| qwen3-embedding-0.6b (Q8_0, `--pooling last`) | 152.8 s | 2254 | 729 | 111,291 |

These match the in-run figures (snowflake 1311-1422 tok/s, Qwen3 723-794 tok/s), so two docling conversions that overlapped the run did not distort them.

## Reranker

bge-reranker-v2-m3 stays. It adds +0.02 to +0.06 nDCG@10 for snowflake without the prefix, and +0.02 on SciFact with it. Its biggest effect is lifting Qwen3, which is consistent with Qwen3's lower first-stage precision. No alternative was tested. The research notes say that public Qwen3-Reranker GGUFs often return broken `/v1/rerank` scores on llama.cpp, and that jina-reranker-v3 is non-commercial and needs a fork.
